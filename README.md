# Library Desk

![Library Desk icon](src/main/resources/com/library/ui/app-icon.png)

A Java 21 and JavaFX library book management system developed for the Software Construction Open-Ended Lab. The application runs through Maven and uses Supabase for authentication and persistent data.

## Features

- Librarian sign-in, in-memory session handling and sign-out.
- Dashboard showing total, Available, Issued and Reserved book counts.
- Add, view, edit and delete books with validation and deletion confirmation.
- Search by ID, title or author, combined with a status filter.
- Read-only activity history generated by database triggers.
- Background HTTP requests, loading states and user-readable errors.

## Requirements

- JDK 21 with JAVA_HOME pointing to the JDK.
- Maven 3.9 or later available on PATH.
- Internet access and a configured Supabase project.
- A registered Supabase Auth user with a matching row in public.librarians.

Verify your tools:

```powershell
java -version
mvn -version
```

## Local configuration

Create a file named `.env` in the project root and fill in your own project settings:

```dotenv
SUPABASE_URL=https://YOUR_PROJECT_REF.supabase.co
SUPABASE_KEY=YOUR_SUPABASE_PUBLISHABLE_OR_ANON_KEY
```

Each nonblank OS environment variable overrides the corresponding `.env` value. Values are trimmed, and the file is optional when both OS variables are provided. Missing settings produce a setup message during sign-in. Run Maven from the project root so the optional file is found.

Use only a publishable or anon client key. Access is enforced by Supabase Authentication, grants and row-level security. Never use a service-role key in the application. `.env` is ignored by Git; do not commit credentials or tokens.

## Database setup

For a new Supabase project, review and run these SQL files in order:

1. `database/schema.sql`
2. `database/policies.sql`
3. `database/activity_logging.sql`

These are initial setup scripts, not repeatable migrations. Do not rerun them on an existing configured project. Create a user through Supabase Authentication, then add its UUID and a display name to `public.librarians`. An Auth account without a librarian profile cannot enter the workspace.

The application does not create accounts or insert activity rows manually. Book mutations are recorded by the database trigger. Historical book IDs in activity logs have no book foreign key, allowing history to survive deletion.

## Run and build

```powershell
mvn javafx:run
```

The JavaFX entry point is `com.library.ui.LibraryFxApp`. The window title and application identity are **Library Desk**. Its open-book icon is included in the resources. No standalone Windows installer is provided.

```powershell
mvn clean test
mvn clean package
mvn javadoc:javadoc
```

Close the running application before a clean build. Maven produces the JAR under `target/`; it is not a bundled executable with its dependencies. Use `mvn javafx:run` to launch.

## Architecture

| Package | Responsibility |
| --- | --- |
| `com.library.ui` | JavaFX application, FXML controllers, search and formatting helpers |
| `com.library.model` | Book, BookStatus, Librarian, LibraryStatistics and ActivityLog |
| `com.library.service` | Authentication, validated book operations and activity retrieval |
| `com.library.repository` | Authenticated book persistence through Supabase REST |
| `com.library.config` | Configuration resolution and HTTP transport |
| `com.library.util` | Reusable input validation |

FXML and CSS are in `src/main/resources/com/library/ui`. Controllers call services; synchronous requests execute in background tasks. Session identity checks prevent stale results from updating a later session. The original `com.library.App` console harness remains available; it creates, edits and deletes a supplied test book and should only be used with disposable records.

For manual acceptance, use a test librarian and disposable books. Check valid/invalid login; Add and duplicate IDs; blank fields; view and empty state; edit and missing records; all three statuses; combined search/filter; cancel/confirm deletion; dashboard counts; activity entries; refresh/restart persistence; logout; network errors; keyboard access and resizing. ## Limitations

- Internet access is required; no offline database or local token persistence is provided.
- Collection searches fetch all books and filter locally without server pagination.
- Activity history is limited to the latest 100 events.
- Statistics and the collection are separate requests and may briefly disagree during concurrent edits.
- New books start Available; status changes are separate actions.
- A failed mutation may already have reached the server; refresh before retrying.
- No student portal, borrowing transaction workflow, fines or payment features are included.
